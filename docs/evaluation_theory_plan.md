# Frame-Level vs. Event-Level Evaluation in Near-Miss Prediction

## 1. The Core Problem: Discrete Events vs. Continuous Time
You are absolutely correct. Your current simulator generates **temporal sequences** (time-series data). A "Near-Miss" is not a single point in time, nor is it just a binary label for the whole scenario. It is a **process** that has:
1.  **Onset:** When the risk first becomes apparent.
2.  **Duration:** How long the risk persists.
3.  **Severity Curve:** How the risk (e.g., TTC) changes over time.
4.  **Offset:** When the situation returns to safe.

### Why Scenario-Level is Insufficient
If Ground Truth says a "Rear-End Conflict" exists from **Frame 50 to 100**:
*   **Method A** detects it from Frame 80 to 90. (Late, short duration).
*   **Method B** detects it from Frame 45 to 105. (Early, slightly over-anxious).
*   **Method C** detects it at Frame 50, drops it at 51, detects again at 99. (Flickering).

In a purely **Scenario-Level** evaluation (which we have now), all three might be marked given a simple `True Positive` because they "detected the event." This hides the fact that **Method A is dangerous** (too late) and **Method C is unreliable** (unstable).

## 2. Theoretical Framework: Evaluation Levels

To rigorously evaluate this, you need a multi-level hierarchy of metrics.

### Level 1: Frame-Level (The "micro" view)
This treats every single frame as an independent classification task.
*   **Concept:** Compare $y_{t}$ (Ground Truth at time $t$) vs $\hat{y}_{t}$ (Prediction at time $t$).
*   **Metrics:** Frame-Accuracy, Frame-F1, Frame-mAP.
*   **Pros:** deeply punishes flickering and latency.
*   **Cons:** Can be overly harsh. Being off by 100ms (1 frame at 10Hz) is mathematically "wrong" but physically irrelevant.

### Level 2: Event-Level / Temporal IoU (The "macro" view)
This treats the "Near-Miss" as a temporal segment (e.g., $[t_{start}, t_{end}]$).
*   **Concept:** Calculate the **Intersection over Union (IoU)** of the time intervals.
    $$ \text{Temporal IoU} = \frac{\text{Duration}(\text{GT} \cap \text{Pred})}{\text{Duration}(\text{GT} \cup \text{Pred})} $$
*   **Metrics:** Average Temporal IoU, Success Rate @ IoU > 0.5.
*   **Pros:** Measures how well the algorithm captures the *duration* of the threat.

### Level 3: Time-to-Event (The "safety" view)
This is specific to collision prediction.
*   **Concept:** How much time before the critical point (TTC=0 or min distance) did the alarm go off?
*   **Metrics:** Mean Warning Time (Time-to-Collision at first detection).

## 4. Recommended Metrics (Aligned with Academic Standards)

Recent literature in traffic anomaly detection (e.g., DoTA, DADA datasets) emphasizes the need for metrics that capture both **detection reliability** and **anticipation time**.

### A. Frame-Level AUC (The Gold Standard)
While F1-score is useful for operational thresholds, academic benchmarks (e.g., CVPR, IEEE ITS) primarily use the **Area Under the Receiver Operating Characteristic Curve (AUC-ROC)** based on frame-level scores.
*   **Definition:** Measures the ability of the model to rank accident frames higher than normal frames across *all* possible thresholds.
*   **Justification:** Avoids the bias of selecting a single threshold.
*   **Reference:** *Yao et al., "DoTA: Unsupervised Detection of Traffic Anomaly in Driving Videos", IEEE TPAMI 2022.*

### B. Time-to-Accident (TTA) / Mean TTA
For collision prediction, the "earliness" of the warning is critical.
*   **Formula:** $\text{mTTA} = \frac{1}{N} \sum_{i=1}^{N} \max(0, t_{end}^{(i)} - t_{start}^{(i)})$
    *   Where $t_{end}$ is the moment of collision/near-miss peak.
    *   Where $t_{start}$ is the first time the risk score crosses a high-precision threshold (e.g., threshold where Precision=80%).
*   **Usage:** Report mTTA at a fixed False Positive Rate (e.g., 1FP per hour).
*   **Reference:** *Fang et al., "DADA: Driver Attention Prediction in Driving Accidents", IEEE T-ITS 2019.*

### C. Temporal Intersection over Union (t-IoU)
Standard for "Action Localization" in video.
*   **Formula:** $\text{t-IoU} = \frac{\text{Intersection Duration}}{\text{Union Duration}}$
*   **Acceptance:** A detection is counted as True Positive only if t-IoU > $\alpha$ (e.g., 0.5).

### D. Conflict Type Classification Accuracy (Sequence-Level) with mAP@t-IoU
*   **Scientific Validation:** Conflict types (e.g., Side-Swipe vs. Cut-In) are inherently defined by **temporal dynamics** (relative motion history and future trajectory), not just static geometry. As validated by major action localization benchmarks (e.g., THUMOS'14, ActivityNet), evaluating classification accuracy requires ensuring the prediction temporally aligns with the ground truth event.
*   **Method:** Establish "True Positive" sequences using an **intersection-over-union (t-IoU)** threshold (typically $\alpha=0.5$). A predicted event counts as a correct classification *only* if:
    1.  The predicted class matches the ground truth class.
    2.  The temporal overlap (t-IoU) > $\alpha$.
*   **Metric:** Mean Average Precision (mAP) at specific t-IoU thresholds (mAP@0.5).
*   **Formula:** $\text{mAP} = \frac{1}{|Classes|} \sum_{c \in Classes} \frac{\text{TP}_c}{\text{TP}_c + \text{FP}_c}$ (where TP requires temporal overlap).

## 5. Proposed Implementation Plan

1.  **Modify `DataGenerator` (See Section 3):**
    *   Ensure all near-miss objects have a distinct role or flag (e.g., `is_risk_object=True`).
    *   Refine `ground_truth_events` generation to be physics-based (TTC threshold) rather than time-window based.

2.  **Calculate Frame-Level Scores:**
    *   Store raw probability scores for every frame: `y_score = [0.1, 0.2, 0.8, ...]`.
    *   Compute `sklearn.metrics.roc_auc_score(y_true, y_score)`.

3.  **Calculate TTA:**
    *   Identifying the first frame where `y_score > threshold`.
    *   Subtract timestamp from Ground Truth `impact_time`.

4.  **Calculate Conflict Type Metrics:**
    *   For each True Positive event (defined by t-IoU > 0.5), compare the **Predicted Event Type** (most frequent class in the sequence) vs. **Ground Truth Event Type**.
    *   Compute Multi-class Confusion Matrix.

5.  **Visualization:**
    *   Plot the **Temporal Action Localization (TAL)** chart: Ground Truth bars vs. Predicted bars on a time axis.
